App Kit runbook

From a reference app to a published design structure

How the Music variant of App Kit was built, written as steps to follow the next time a set of tokens and components is taken from a real app. The order matters: each stage produces the evidence the next one depends on.

Rules of evidence

  1. 1A value needs an instrument. A hex with no capture, command and sample count behind it is a note, and the table says so.
  2. 2A file name is not an instrument. The state a capture shows is read from the capture, never from what it was called.
  3. 3Every check gets two inputs. One it must fail on and one it must pass on. A check that has only ever blocked has not been seen to work.
  4. 4An exit code is not the effect. After a build, a publish or a mutation, look at the thing that should have changed.
  5. 5Measured and decided are different tokens. When a measured colour fails contrast, keep it and add a stepped one beside it.

Worked example. Music variant, 2 October 2026: 17 colour tokens in two appearances make 34 cells. 25 are measured, 9 are derived, and none is left without an instrument. Six were unsupported that morning; this run closed them from 12 captures and changed two values by one step each.

1

Scope the source

Name the one place values come from and the states you need from it.

Done when
Every cell of the matrix is marked needed or not needed, and the out-of-scope list has a reason per item.
Trap
A scrape of music.apple.com gave #D60017 for the accent. The Mac app measures #FA233B.

Skill: apple-docs before reasoning about any Apple framework symbol.

2

Capture

Get one still per needed cell without disturbing the screen you are working on.

# where the virtual display is
~/bin/vdisplay.sh status
# show the window without activating, then move it off screen (AX, no activation)
osascript -e 'tell application "Music" to reopen'
music-park -228 -1340
# select a row by script, then shoot the window by id
osascript -e 'tell application "Music" to reveal track 3 of playlist "Jump rope"'
screencapture -o -x -l <window-id> row-selected-inactive-dark-vd.png
Done when
Each needed cell has a PNG on disk, and the before capture shows the state absent, which proves the after capture is of now.
Trap
Focus returns to the terminal about a second after the app is activated. A key-window capture has to be taken inside that second, and a not-key capture after it.
3

Witness the state

Read what each capture actually shows before any colour from it is trusted.

/usr/bin/python3 build/source/swatch-scan.py --selftest
/usr/bin/python3 build/source/swatch-scan.py <capture.png> --lights
Done when
Every capture a token leans on has a witnessed state in the log.
Trap
album-selected-inactive-dark.png was shot with the window key. Its grey was a key window with an unfocused list, and it stood in as the inactive value for weeks.
4

Measure

Turn captures into numbers, each with the command that produced it.

# coordinates are image pixels; scale is 2 above 1800px wide, else 1
swatch-scan.py <png> --hist Y:X0:X1        # fill: top colours and sample count
swatch-scan.py <png> --glyph X0:Y0:X1:Y1   # label: interior, count, background
swatch-scan.py <png> --extent X:Y          # shape: fill, x range, y range in pt
Done when
Every number in the log sits beside its capture, command, window state and sample count, and one line says whether each prediction held.
Traps
A run reported as 740 of 740 was the width of the sample window. A seed on a text line gave a 222pt extent for a 758pt ground. Four sessions of pixel scans could not explain a 572pt line end that the Accessibility tree gave at once.
5

Record provenance

Say, per token and per appearance, how the value is known.

ClassMeansWhat closes it
MeasuredSampled from a still capture whose state was witnessed.Nothing. Name the capture, the state and the count.
DerivedComputed from measured values, for example an alpha solved from a fill over a backdrop, or a grey stepped to clear 4.5:1.Nothing. State the rule and let the build recompute it.
No instrumentThe log states a value and names no capture or method.Stages 2 to 4 for that cell.
Not observedAssumed, usually from the other appearance.Stages 2 to 4 for that cell.
Done when
A search of the rebuilt README for the two weak class names returns the count you expect, and returns a non-zero count on the previous commit.
Trap
A README that says every value was measured, written before anyone checked. The table replaced that sentence.
6

Tokens and gates

Write the values once, in the generator, behind checks that can fail.

# the copy resolves its sources relative to itself, so give it the same layout
mkdir -p $S/mut/build && cp build/app_build.py $S/mut/build/
ln -sfn "$PWD/build/source" $S/mut/build/source
# edit the copy, grep that the edit is there, then expect exit 1 with the gate's own message
/opt/homebrew/bin/python3 $S/mut/build/app_build.py $S/src $S/mut-out
Done when
The real build passes, each mutant fails with the message of the gate it targets, and the unmutated copy in the same layout passes.
Trap
A mutant that exits 1 with FileNotFoundError has not tested anything. It looks exactly like a gate firing until you read the last line.

Skills: design:design-system (extend) before adding a token, design:accessibility-review for any colour.

7

Components and build

Generate the tree; never edit what the generator writes.

S=<scratch dir>
mkdir -p $S/src && ln -sfn "$PWD/build/source/decena-apps-2026-09-24" $S/src/project
/opt/homebrew/bin/python3 build/app_build.py $S/src $S/out
diff -rq $S/out/project design-system/project
diff -q $S/out/swift/AppKit.swift swift/AppKit.swift
Done when
The build exits 0 with no NOT CHECKED line, and the second diff shows one file.
Traps
A new file under build/ needs git add -f or it stages nothing and says nothing. A changed value also lives in prose: the Play label moved to black and a CSS comment still said near-black.
8

Verify

Run the composed thing, and have someone other than the author check it.

Done when
Both reviews are back, every gap is either fixed in a new commit or recorded as left, and no finding rests on a reviewer's word alone.
Trap
A list of pairs cannot see the cascade between them. A hover rule tied the selected rule on specificity and painted 1.27:1 while all 33 pairs passed.

Skills: design:design-critique on a side-by-side screenshot, design:accessibility-review for hover and hit targets.

9

Publish

Send only what changed, to the recorded address, and read it back.

Done when
Each sent file's hash on the artifact equals its hash in the tree, and the version numbers are written in the status log.
Traps
Reading files by path does not count as viewing the artifact; the publish is refused until the artifact itself is read. index.d.ts needs an explicit text/plain type, and its refusal publishes nothing at all.
10

Log and hand off

Leave the next session able to start without this one.

Done when
The working tree is clean, the remote matches, and the Next Up section names at most three things.
Trap
A background agent can outlive the session that started it and keep committing. Check for one before editing the files it owns, and re-run its numbers before closing its tasks.

Practices that have paid for themselves

  1. 1Edit the generator. Anything under design-system/project/ or swift/ is rewritten by the next build.
  2. 2Drive other apps on the virtual display. Save and restore the cursor, the frontmost app, and the window's position and open state.
  3. 3One appearance per read. Set data-theme in one call and read computed styles in the next, or the background comes back from the previous theme.
  4. 4Bust the bundle cache. Add ?v=<epoch> and have the page say which build it loaded before measuring.
  5. 5Look at the pixels. A render check that only asserts the output is not empty passes a broken image.
  6. 6Ship ratios and gaps, not sizes. Card sizes follow a sidebar the user can resize; gaps and aspect ratios hold.
  7. 7Colour never carries a state alone. Pair it with a word or a glyph, and use no emoji.
  8. 8Keep reads out of the main session. Send a long log or a diff to a subagent, then check its specific numbers yourself.
B

Where to look, and what to trust first

Each source below was opened and checked on 2 October 2026. Every one has a limit, and the limit is the reason the runbook measures.

  1. 1For a value, the running app. No document gives the pixel. Apple's guidelines say not to hard-code system colours, and the design kits are redraws.
  2. 2For intent, the dated primary source. Use the page that carries a version or an update date, and write that date beside the claim.
  3. 3For behaviour, the documentation tool, never memory. apple-docs for Apple frameworks, context7 for libraries, claude-docs for Claude Code.
  4. 4A draft is not a requirement. Check the status line of a specification before citing it.

Apple platform conventions

SourceAuthority forWhat it cannot tell you
Human Interface GuidelinesPlatform conventions and component intent. The Materials page covers Liquid Glass on macOS (updated June and September 2025); Color was updated December 2025.Pixel values. It describes intent and tells you not to hard-code system colours.
Apple Design ResourcesOfficial Figma and Sketch kits, now listed for macOS 27, with SF Symbols 27 and Icon Composer.What an app really draws. The kits are redraws, not measurements.
UI element colors (AppKit)The semantic colour names that adapt to appearance.Resolved RGB. It gives names only.
Material (SwiftUI)The blur and vibrancy materials and their thickness levels.Liquid Glass, which is a separate API, and how any material looks over your desktop.

Trust first: the guidelines, by their dated update table. Reach them through the apple-docs tool before reasoning about a symbol.

Accessibility and contrast

SourceAuthority forWhat it cannot tell you
WCAG 2.2The current W3C Recommendation, dated 12 December 2024. Its normative text is what a contrast floor is measured against.Whether a design reads well. It sets floors.
Understanding 1.4.3Text contrast: 4.5:1, and 3:1 for large text.It is informative, not normative.
Understanding 1.4.11Controls and graphics: 3:1.It is informative, not normative.
HIG AccessibilityApple's own table: 4.5:1 up to 17pt, 3:1 at 18pt or bold.Anything beyond what WCAG already requires.
WCAG 3.0Nothing yet. It is a Working Draft dated 10 September 2026, and its text-contrast method is undecided.Do not cite it, or any contrast method tied to it, as a requirement.

Trust first: the WCAG 2.2 normative text. The build's contrast gate computes that ratio, and design:accessibility-review covers what a list of pairs cannot.

Token format and naming

SourceAuthority forWhat it cannot tell you
Design Tokens Format Module 2025.10The stable interchange format, a Final Community Group Report of 28 October 2025.It is not a W3C Standard. The drafts address says not to treat it as authoritative.
Naming Tokens in Design Systems, Nathan Curtis, 2020Naming levels: namespace, object, base, modifier.A tier model. It covers naming only.
The Design System artifact's own instructionsThe shape the published page reads: each family is a list of name, value and usage.It cannot read the name-to-value map of the format above, so convert before writing tokens.json.

Trust first: for interchange, the 2025.10 address. For this system, the artifact's list shape, because that is what renders.

Process and governance

SourceAuthority forWhat it cannot tell you
GOV.UK Design System contribution criteriaConcrete, published criteria for what may enter a system.They are tuned to government services.
Design Systems 101, Nielsen Norman GroupDefinitions, governance, and the choice to adopt, adapt or build. Reviewed August 2026.Depth. It is an introduction.

Colour measurement on a Mac

SourceAuthority forWhat it cannot tell you
The profile in your own capture: sips -g space -g profile <file>What the numbers in that file mean. Captures here carry Display P3 from the built-in display and Virtual 16:9 from the virtual one.The sRGB value. Convert first with sips -m.
TN2313, Best Practices for Color ManagementWhy RGB values mean something only when tagged with a profile.It is archived, dated 2014, and does not mention screenshots.
